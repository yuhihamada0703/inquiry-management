# 要件定義書

## プロジェクト概要

| 項目 | 内容 |
|------|------|
| プロジェクト名 | Inquiry Management（問い合わせ管理アプリ） |
| 目的 | 顧客からの問い合わせを一元管理し、対応状況をチームで共有する |
| 対象ユーザー | カスタマーサポート担当者 |
| 作成日 | 2026-06-11 |

---

## 背景と課題

問い合わせ対応をスプレッドシートやメールのみで管理すると、  
対応漏れ・二重対応・進捗の不透明さが発生しやすい。  
本アプリはそれらを解消するためのシンプルな問い合わせ管理ツールとして位置づける。

---

## 機能要件

### 問い合わせ管理（CRUD）

| # | 機能 | 説明 |
|---|------|------|
| F-01 | 問い合わせ登録 | 件名・内容・顧客名（ふりがな）・担当者・メール・対応期限・内部メモを入力して登録 |
| F-02 | 問い合わせ一覧表示 | 登録された問い合わせをカンバン形式で表示 |
| F-03 | 問い合わせ詳細表示 | 選択した問い合わせの全情報をダイアログで表示 |
| F-04 | 問い合わせ編集 | 登録済み情報を更新（ステータス変更も可） |
| F-05 | 問い合わせ論理削除 | 「履歴へ移動」で論理削除（deleted_at を記録） |
| F-05b | 完全削除 | 管理者パスワード認証後に物理削除 |

### ステータス管理

| # | 機能 | 説明 |
|---|------|------|
| F-06 | ステータス表示 | 未対応 / 対応中 / 回答待ち / 完了 の4種類 |
| F-07 | ドラッグ&ドロップによるステータス変更 | カード全体をドラッグしてカラム間で移動 |
| F-08 | 同一カラム内並び替え | カード全体をドラッグしてカラム内の順序を変更 |

### 並び替え・フィルタ

| # | 機能 | 説明 |
|---|------|------|
| F-09 | 顧客名ソート | ふりがな順（読み順）で昇順・降順に並び替え |
| F-10 | 担当者ソート | ふりがな順で昇順・降順に並び替え |
| F-11 | 期限順ソート | 対応期限が近い順・遠い順に並び替え |
| F-12 | 作成日時ソート | 登録日時順に並び替え |
| F-13 | キーワード検索 | 件名・内容・顧客名でフリーワード検索 |

### 削除済み履歴

| # | 機能 | 説明 |
|---|------|------|
| F-14 | 履歴一覧表示 | 論理削除済み問い合わせの一覧表示 |
| F-15 | 完全削除 | 管理者パスワード（環境変数で設定）入力後に物理削除 |

### データ永続化

| # | 機能 | 説明 |
|---|------|------|
| F-16 | データベース保存 | MySQLへ永続化 |
| F-17 | ページネーション | バックエンド API は20件/ページのページネーションに対応。カンバンビューはDnDの都合上 `size=200` で全件取得するためページング UI は提供しない。 |

---

## 非機能要件

| 項目 | 要件 |
|------|------|
| パフォーマンス | 一覧取得は 500ms 以内に応答 |
| 可用性 | EC2 + RDS 構成でサービス提供 |
| セキュリティ | CORS設定、環境変数による機密情報管理、管理者パスワードによる完全削除保護 |
| ブラウザ対応 | Chrome / Edge / Safari 最新版 |
| レスポンシブ | PC・タブレットに対応 |

---

## 制約条件

- AWSはEC2とRDSのみ使用（ALB・ECS等は使用しない）
- 認証機能はスコープ外（将来拡張として考慮）
- データベースはMySQL 8.0
- Flywayマイグレーションはローカルでは無効化（手動適用）

---

## スコープ外

- ユーザー認証・ロール管理
- メール通知
- 添付ファイル管理
- 外部サービス連携（Slack等）
